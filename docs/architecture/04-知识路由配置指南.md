# 05 - 知识路由配置指南（实操）

---

## 0. 知识路由是什么

> **知识路由 = 自动知识问答前面的一个「预选器」。**

当知识库文档越来越多，如果每次都全库检索，不仅**速度变慢**，还容易**召回不相关的文档**。

知识路由在真正检索之前，先帮系统判断三件事：

1. 当前问题属于哪个**知识范围**
2. 这个范围下更像哪个**知识主题**
3. 哪篇**文档**最适合作为回答依据

### 配置顺序（页面上的四步）

```
范围 → 主题 → 画像 → 关联
```

> 把这四步配置清楚，后面的自动知识问答就能更稳定地命中正确文档。

---

## 1. 进入知识路由页面

最上方展示一组总览数据：

| 指标 | 含义 |
|------|------|
| **知识范围** | 当前已配置了多少个大类边界 |
| **知识主题** | 范围下面已沉淀了多少个可回答单元 |
| **文档数** | 当前参与知识路由画像和元数据维护的文档数 |
| **已补元数据文档** | 至少填写了范围、业务类目或标签的文档数 |
| **已保存关联** | 已建立好的主题和文档关联数量 |
| **未关联主题** | 还没有绑定任何文档的主题数量 |

### 范围覆盖率统计

展示每个知识范围的覆盖情况，每个范围下可直接看到：

- 主题数量
- 已覆盖主题数
- **未关联主题数**
- 文档数

> **配置巡检用法**：如果某个范围下面的「未关联主题」不为 0，通常说明后面的**主题文档关联还没有配置完整**。

### 右上角常用按钮

| 按钮 | 作用 |
|------|------|
| 刷新数据 | 手动刷新当前统计结果 |
| **批量重建画像** | 当文档内容或元数据更新后，统一重新生成文档画像 |

---

## 2. 第一步：配置知识范围

**作用**：把知识库按业务域划出边界。可理解为一个「一级分类」。

**示例**：
- ✅ `客服平台上线运营`
- ✅ `XX-200智能网关`
- ❌ `灰度验证回滚流程` ← 这个太细，应该作为**知识主题**而不是范围

### 配置要点

- 范围**不应该写得太细**，而应**足够稳定、足够概括**
- 页面支持按 **范围编码、名称或描述** 筛选
- 缺大类时可点「新建范围」补充

> **重要经验**：**先把范围定清楚，后面的主题、画像和关联配置才会更稳。**
> 因为自动路由时，系统通常会**先按范围做第一轮收敛**。

---

## 3. 第二步：配置知识主题

**知识主题 = 该范围下的「可回答单元」**。

先通过左侧下拉框选择某个范围，再查看该范围下已配置的主题列表。

### 主题卡片展示的信息

每个主题卡片里除了主题名称，还能直接看到两类关键配置：

| 配置 | 作用 | 示例取值 |
|------|------|---------|
| **回答形式** | 影响系统后续组织答案的方式 | 步骤型回答、列表型回答 |
| **执行偏好** | 影响检索策略选择 | 普通检索优先 |

**如何选择回答形式：**

| 主题性质 | 推荐配置 |
|---------|---------|
| 流程类问题（如「上线总流程」） | **步骤型回答** |
| 概念枚举/要点总结（如「治理项有哪些」） | **列表型回答** |

> 右上角「新建主题」用于新增；搜索框支持按 **主题编码、名称、别名或描述** 筛选。

### 3.1 主题详情需维护的字段

| 字段 | 示例 |
|------|------|
| 主题编码 | `platform_go_live_process` |
| 主题名称 | 平台上线总流程 |
| 所属范围 | `customer_service_platform_ops` |
| 回答形式 | 步骤型回答 |
| 执行偏好 | 普通检索优先 |
| 排序值 | - |
| **描述** | - |
| **别名** | - |
| **典型问题** | - |

> **这些字段不是「可有可无」的补充信息，而是知识路由能不能配准的关键依据。**

### 3.2 必须补完整的三类内容 ⭐

| 内容 | 作用 |
|------|------|
| **描述** | 告诉系统这个主题到底覆盖什么问题 |
| **别名** | 补足用户常见的不同叫法 |
| **典型问题** | 直接提供用户真实会怎么问 |

**示例**（主题「平台上线总流程」）：
```
别名：上线流程、上线步骤、项目上线、上线里程碑
典型问题：平台上线总流程有哪几个阶段、项目上线要经过哪些里程碑
```

> 这些内容一旦补全，知识路由在做主题匹配时，**就不再只依赖一个简短标题，而是有更完整的判断依据**。

---

## 4. 第三步：检查文档画像

确认文档有没有被系统「理解清楚」。

### 文档画像详情展示的信息

| 信息 |
|------|
| 文档名称 |
| 元数据 |
| 摘要 |
| 文档类型（如 `manual`） |
| 画像来源（如 `manual`） |
| **图能力**（如 `outline / item / assist`） |
| 核心主题数 |
| **核心主题** |
| **示例问题** |

### 判断标准

> **如果摘要、核心主题或示例问题明显不准确，说明这份文档的画像质量还不够好。**

### 可用操作

| 操作 | 作用 |
|------|------|
| 查看画像 | 查看当前画像内容 |
| **重新生成** | 重新生成这份文档的画像 |

> **建议顺序**：先让文档画像尽量准确，**再做主题文档关联**，后面的路由效果会更稳定。

---

## 5. 第四步：配置主题文档关联

**作用**：把「哪个主题该优先看哪份文档」**显式维护下来**，低置信自动路由时会直接受益。

> **这一步非常重要**。有些主题虽然可以通过语义匹配大概猜到文档，但如果你**已经明确知道某个主题最应该命中哪篇文档**，就应该在这里把关系手动建好。

### 页面提供的操作

| 操作 | 说明 |
|------|------|
| 按范围切换 | 查看当前业务域下的关联 |
| 搜索框 | 按 **主题、文档、原因** 过滤 |
| **新建关联** | 新增一条主题和文档的绑定关系 |
| 刷新 | 重新拉取当前列表 |

### 5.1 新建主题文档关联需填写

| 字段 | 配置建议 |
|------|---------|
| **选择主题** | 告诉系统你要绑定的是哪一个知识主题 |
| **选择文档** | 告诉系统这个主题最应该优先参考哪篇文档 |
| **分数** | 代表这条关联关系的强弱，**分数越高优先级越高**（默认 `0.9000`） |
| **关联原因** | 建议写清「为什么这篇文档适合这个主题」，便于后续排查和维护 |

> 默认展示 `0.9000`，说明这类**手工关联通常以较高置信度建立**。

### 5.2 关联结果的特点

- **同一个主题可以关联多篇文档**
- 每条关联都带一个**分数**
- 每条关联后展示一段**关联原因**

> **适用场景**：在真实业务里，一个主题往往不只由一篇文档支撑，而是涉及**主文档、补充文档和边界文档**。
> 通过显式关联，系统在自动路由时更容易先命中正确资料。

---

## 6. 推荐的配置顺序（首次配置）

```
8.1 先定知识范围
      按业务域把范围划清楚，不要一开始就拆得过细

8.2 再补知识主题
      围绕「用户实际会问的问题」设计主题
      ⚠️ 不要直接照着文档章节名机械复制

8.3 然后检查文档画像
      确保摘要、核心主题、示例问题足够准确
      不准确就先重建画像

8.4 最后做主题文档关联
      优先把高频主题、核心流程主题、容易混淆的主题先手动关联起来
```

---

## 7. 配置知识路由的几个建议

| # | 建议 |
|---|------|
| 1 | **范围**要稳定，尽量按**业务域**划分，不要用临时任务名充当范围 |
| 2 | **主题**要聚焦，一个主题最好只回答**一类核心问题** |
| 3 | **别名**和**典型问题**尽量写成**用户真实会输入的说法** |
| 4 | **文档画像**不准时，不要急着做关联，**先重新生成画像** |
| 5 | **关联原因**不要只写「相关」，最好明确写出是**流程覆盖、指标覆盖还是场景覆盖** |
| 6 | 对于高价值主题，可以关联**多篇文档**，但最好**通过分数拉开优先级** |

---

## 8. 总结

> 把这套配置维护好之后，自动知识问答就**不再是「全库盲搜」**，而会优先沿着你配置好的
> **知识范围 → 知识主题 → 主题文档关系** 去收敛目标文档，
> 最终让回答**更准、速度更快、噪声更低**。
