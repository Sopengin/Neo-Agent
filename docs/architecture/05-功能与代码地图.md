# 05 - 功能与代码地图

---

## 0. 使用方式

这是一份**功能索引** —— 按功能找到对应的**核心类 + 关键方法**，在 IDE 里直接跳转源码。

**源码路径说明**：

```
默认根路径：neo-agent-business/neo-agent-business-chat/src/main/java/com/sopengin/neo/ai/
```

> 未特别标注模块的，都在上述位置。少数基础设施类在其他模块：
> - `RedisLeaseManager` → `neo-agent-redisson-framework`
> - 通用工具类 → `neo-agent-common-frame`

**使用方式**：
1. 按下表的功能名检索
2. 用核心类 / 方法名在 IDE 里直接跳转
3. 完整执行流程见 [`01-核心架构设计.md`](01-核心架构设计.md)
4. 建议启动服务后打断点跟一遍完整链路

## 1. 对话入口与生命周期管理

> 整个系统的起点：一个对话请求进来后，系统怎么接住它、怎么管理生命周期。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| SSE 流式对话入口 | `BusinessChatController` | `stream()` | 接收前端请求，返回 SSE 流 |
| 对话主流程编排 | `BusinessChatService` | `openConversationStream()` | 整个对话的总调度，从头到尾 |
| 会话租约（防并发） | `BusinessChatService` | `claimConversationLease()` | 用 Redis 分布式锁防止同一会话重复请求 |
| JVM 任务注册 | `ChatRuntimeRegistry` | `register()` / `remove()` | 单机级别的任务去重 |
| 停止生成 | `BusinessChatService` | `stopConversation()` | 用户点「停止」时的处理逻辑 |

---

## 2. 执行前的准备流程（五步决策链）

> 请求进来后不是直接丢给大模型，而是先经过一系列准备工作，决定该怎么回答。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| **准备流程总编排** | `ChatPreparationOrchestrator` | `prepare()` | **五步决策链的总入口** |
| 会话记忆加载 | `ConversationMemoryService` | `loadMemoryContext()` | 加载历史对话摘要和最近几轮原文 |
| 问题改写与拆分 | `ChatQueryRewriteService` | `rewrite()` | 改写成更适合检索的形式，必要时拆成子问题 |
| **知识路由（三层漏斗）** | `KnowledgeRouteServiceImpl` | `route()` | 从 Scope→Topic→Document 逐层缩小范围 |
| 文档问题路由 | `DocumentQuestionRouter` | `route()` | 判断该用哪种执行模式（RAG/图结构/开放问答） |
| 执行计划装配 | `BusinessChatService` | `prepareExecutionPlan()` | 把前面的决策结果组装成最终执行计划 |

---

## 3. 执行器体系（五种执行模式）

> 准备工作做完后，系统根据执行计划选择对应的执行器来真正回答问题。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| 执行器注册与分发 | `ConversationExecutorRegistry` | `get()` | 根据 `ExecutionMode` 找到对应执行器 |
| **RAG 知识问答** | `RagChatExecutor` | `execute()` | 标准的检索增强生成流程 |
| 图结构导航（仅结构） | `GraphOnlyExecutor` | `execute()` | 只回答文档结构相关的问题 |
| 图结构 + 证据 | `GraphThenEvidenceExecutor` | `execute()` | 先定位章节，再读取具体内容 |
| **ReAct 开放问答** | `ReactAgentExecutor` | `execute()` | 带工具调用的多步推理 Agent |
| 澄清反问 | `ClarificationExecutor` | `execute()` | 问题模糊时反问用户 |

---

## 4. RAG 检索引擎 ⭐

> 项目中最复杂的模块之一，涉及双通道检索、融合排序、证据预算控制等。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| **检索引擎总入口** | `RagRetrievalEngine` | `retrieve()` | 编排整个检索流程 |
| **向量检索通道** | `VectorRetrievalChannel` | `retrieve()` | 基于 PGVector 的语义相似度检索 |
| **关键词检索通道** | `KeywordRetrievalChannel` | `retrieve()` | 基于 Elasticsearch 的关键词检索 |
| **RRF 融合排序** | `RagRetrievalEngine` | 内部方法 | 把两个通道的结果用 RRF 算法合并 |
| **父块提升** | `DocumentKnowledgeService` | `elevateToParentBlocks()` | 小块检索精准，大块回答完整 |
| **Rerank 重排序** | `HttpDocumentRerankPostProcessor` | `postProcess()` | 调用外部模型对结果二次排序 |
| **证据预算控制** | `RagPromptAssemblyService` | `assemble()` | 控制塞给大模型的证据 token 量 |

---

## 5. 会话记忆

> 支持三种记忆策略，从无状态到长期摘要压缩都有。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| 记忆加载 | `PersistentConversationMemoryService` | `loadMemoryContext()` | 加载长期摘要 + 最近几轮原文 |
| **摘要压缩** | `PersistentConversationMemoryService` | `refreshConversationSummaryAsync()` | 用 LLM 把历史对话压缩成结构化摘要 |
| 摘要合并 | `PersistentConversationMemoryService` | `mergeSummaryPayload()` | 增量合并新对话到已有摘要 |

## 6. 知识路由（三层漏斗）

> 系统中有多个知识库时，怎么判断用户的问题该去哪个知识库找答案。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| **三层路由决策** | `KnowledgeRouteServiceImpl` | `route()` | Scope→Topic→Document 逐层筛选 |
| 路由索引 | `ElasticsearchKnowledgeRouteIndexService` | — | 基于 ES 的路由候选索引 |
| **影子路由（质量观测）** | `KnowledgeRouteServiceImpl` | `recordShadowRoute()` | 用户手动选文档时，后台静默跑一次路由做对比 |
| 知识域管理 | `KnowledgeManageServiceImpl` | CRUD 方法 | Scope 和 Topic 的增删改查 |

## 7. 文档全生命周期管理

> 从文档上传到最终可被检索，经历解析、分块、向量化、索引构建等一系列步骤。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| 文档上传 | `DocumentManageServiceImpl` | `upload()` | 接收文件，存到 MinIO |
| **多格式解析** | `TikaDocumentParserService` | `parse()` | 用 Apache Tika 解析 PDF/Word/Markdown 等 |
| **分块策略推荐** | `DocumentStrategyServiceImpl` | `recommend()` | 根据文档特征推荐最佳分块策略 |
| **异步处理管线** | `DocumentAsyncProcessServiceImpl` | `process()` | Kafka 驱动的异步处理流水线 |
| 向量化入库 | `DefaultDocumentVectorGateway` | `store()` | 把文本块转成向量存入 PGVector |
| 结构树构建 | `DocumentStructureNodeServiceImpl` | — | 解析文档的层级结构（标题/段落/列表） |
| **Neo4j 图写入** | `Neo4jDocumentStructureGraphService` | — | 把文档结构写入 Neo4j 图数据库 |
| ES 导航索引 | `ElasticsearchDocumentNavigationIndexService` | — | 构建章节级别的搜索索引 |

## 8. 图结构查询引擎

> 文档结构信息存在 Neo4j 里，这个引擎负责回答「这个文档有哪些章节」「某章节下面有什么内容」这类结构性问题。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| **图查询引擎** | `StructureGraphQueryEngine` | `findSectionWithSiblings()` / `findSectionWithChildren()` | 查询章节的兄弟节点或子节点 |
| 图结果渲染 | `GraphAnswerRenderer` | `renderGraphAnswer()` | 把图查询结果转成自然语言回答 |
| 复合图服务 | `CompositeDocumentStructureGraphService` | — | **Neo4j + MySQL 双引擎，互为备份** |

## 9. 工具调用（ReAct Agent）

> 开放式问答模式下，Agent 可以调用外部工具来获取信息。

| 功能 | 核心类 | 关键方法 | 一句话说明 |
|------|-------|---------|-----------|
| **Tavily 网络搜索** | `TavilySearchTool` | `search()` | 调用 Tavily API 搜索互联网 |

## 12. 集群安全与并发控制

> 生产环境多实例部署时，怎么保证同一个会话不会被多个节点同时处理。

| 功能 | 核心类（模块） | 关键方法 | 一句话说明 |
|------|--------------|---------|-----------|
| **Redis 分布式租约** | `RedisLeaseManager`（redisson 模块） | `acquire()` / `renew()` / `release()` | 集群级别的会话互斥锁 |
| 租约自动续期 | `BusinessChatService` | `startLeaseRenewal()` | **10 秒续期一次，30 秒 TTL** |
| 优雅清理 | `BusinessChatService` | `cleanup()` | finally 块中释放所有资源 |
